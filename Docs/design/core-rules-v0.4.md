# 핵심 룰 v0.4 — 쪼꼬미 공성전 (완성판 1차)

작성일 2026-09-26 (9절까지 같은 날 갱신). v0.3 (실시간 공격 디펜스) 위에 **타워 합성**, **팀전 밸런스**, **후반 압박**, 그리고 그림·움직임·이펙트·소리·타이틀/결과 화면까지 얹어 "한 판 온전히 돌아가는 게임"으로 만든 판이다. v0.3 문서의 규칙은 여기서 바꾼 것 말고는 그대로다.

## 1. 게임 이름·화면

- 이름: **쪼꼬미 공성전** (Chokkomi Siege). 아기자기한 픽셀 chibi 스타일, 크림색 UI.
- 씬은 `Assets/Scenes/Main.unity` 하나. 타이틀(모드 선택 → 1v1 / 2v2 / 3v3, 게임 방법, 합성표, 소리 설정) → 경기 → 결과(전적·통계, 다시 하기 / 타이틀로).
- 2v2·3v3 는 **봇 팀원**과 함께 한다 (온라인은 아직). 사람은 팀 0 의 0번 자리. 팀원 타워에는 P2·P3 표시.

## 2. 타워 합성 (새 규칙)

### 2-1. 별 합치기 (같은 타워 3개)

| 별 | 조건 | 공격 배율 | 사거리 |
|---|---|---|---|
| ★1 | 기본 | ×1 | 기본 |
| ★2 | 같은 정의·같은 별 ★1 × 3 | **×2.2** | +0.5칸 |
| ★3 | ★2 × 3 (= ★1 9개) | **×5** | +1칸 |

- 재료는 **같은 주인**의 타워여야 한다 (팀원 것과는 못 합침). 자리는 클릭한 타워 자리, 즉시 완성(건설 시간 없음). 재료 중 하나라도 강화면 강화 유지.
- 오라(드루이드·드론)도 별을 따라 ×1.5 / ×2.
- 판매 환불 = 비용 × 3^(별−1) × (강화 2) × 80%.
- 의도: 3개 합이 DPS ×3 인데 ★2 는 ×2.2 → DPS 는 손해지만 **슬롯 2칸을 되찾고** 사거리가 늘고 강화 비용이 하나로 줄어든다. 롤토체스처럼 "같은 걸 모으는" 재미.

### 2-2. 레시피 합성 (다른 타워 2개 → 새 타워, 8종)

| 결과 | 재료 | 비용(합) | 특징 |
|---|---|---|---|
| 불화살 사수 (불·궁수) | 나무 궁수 + 화염 창탑 | 13 | 공9 1.2/초 사3.5 대공 화상 3/초 |
| 가시 폭발꽃 (숲·마법사) | 가시 덤불 + 불꽃 술사 | 15 | 공10 0.6/초 사2 광역1.5 감속30% |
| 화염 방사기 (기계·마법사) | 태엽 포탑 + 불꽃 술사 | 17 | 공7 1.6/초 사2.5 광역0.8 화상 3/초 |
| 거목 투석기 (숲·전사) | 강철 대포 + 숲의 드루이드 | 25 | 공30 0.3/초 사4 광역1.2 거인 2배 |
| 번개 비행선 (기계·궁수) | 불사조 + 수리 드론 | 22 | 공14 0.8/초 사4 대공 공중 2배 광역0.6 |
| 저격 드론 (기계·궁수) | 나무 궁수 + 수리 드론 | 14 | 공22 0.5/초 사5.5 대공 |
| 철갑 가시 (기계·전사) | 가시 덤불 + 강철 대포 | 21 | 공18 0.5/초 사2 감속40% 거인 2배 |
| 화염 정령 (불·마법사) | 숲의 드루이드 + 불꽃 술사 | 19 | 공6 0.8/초 사2.5 광역1 주변 타워 공격 +20% |

- 순서 무관, 같은 주인, 결과는 클릭한 타워 자리에 ★1 로 즉시. 합성 타워끼리는 다시 합성 못 하지만 같은 합성 타워 3개로 ★은 올릴 수 있다.
- 합성 타워는 상점에 없다. 계열·직업이 재료와 달라지므로 시너지 짜기가 퍼즐이 된다.
- 봇: 빈 슬롯이 2칸 이하가 되면 별 합치기 → 레시피 합성 순으로 시도한다.

### 2-3. 조작

타워 클릭 → 아래 행동 패널: [강화 N골드] [판매 +N] [★n 합치기] [합성 → 결과 이름]. 우클릭은 바로 판매. [합성표] 버튼(상단·타이틀)에서 레시피를 본다.

짝이 여럿이면 버튼에 "(고르기)"가 붙고, 누르면 후보 타워가 하늘색으로 깜빡인다. 합성은 짝 하나를, ★ 합치기는 소모할 두 개를 차례로 클릭한다 (자리가 중요하니까). ESC 나 다른 곳 클릭으로 취소. 명령은 `Fuse(a, b)` / `MergeWith(a, m1, m2)` 로 고른 타워 id 가 그대로 실린다 (온라인도 동일).

## 3. 밸런스 (봇 대전 스윕, SimpleBot vs SimpleBot{Aggression=80}, 16판)

### 3-1. 인원별 기본값 (바뀜)

| | 1v1 | 2v2 | 3v3 |
|---|---|---|---|
| 라인 폭 | 4 | **5** (전 6) | **6** (전 8) |
| 기지 체력 | **40** (전 60) | **120** (전 90) | **300** (전 120) |
| 기본 웨이브 규모 | ×1 | **×1.3** (전 1.6) | **×1.3** (전 2.2) |

- 폭이 넓을수록 타워 사거리 커버가 옅어져 팀전이 일방적으로 기지 파괴로 끝났다 (3v3 폭 8: 16/16 파괴, 평균 5분). 폭을 줄이고 기지 체력을 인원 비례보다 크게 올렸다.
- 결과: 1v1 파괴 0/16 (평균 누수 20/40, 접전), 2v2 파괴 1/16, 3v3 파괴 9/16 (평균 578초). 팀전은 보내기가 3배로 쌓이므로 아직 파괴가 잦다. 사람 플레이 뒤 조정.
- 처치 골드를 "팀원 전원 지급"으로 바꿔 봤더니 봇이 그 돈으로 더 보내서 오히려 파괴가 늘었다 → 원래대로 **팀 균등 분배** 유지.

### 3-2. 후반 압박 (새 규칙)

10번째 기본 웨이브부터 웨이브마다 **기본 웨이브 체력 +8%** (19번째 웨이브 +80%). 봇 대전에서는 결과에 거의 영향이 없었지만(봇 방어가 합성으로 같이 강해짐), 사람이 방어를 소홀히 하면 후반에 새기 시작하도록 둔다. `LaneConfig.LateWaveIndex/LateWaveStepPercent`.

### 3-3. 합성 사용량

1v1 20판에서 별 합치기 567회(★3 20회), 레시피 합성 545회 — 봇이 슬롯이 차면 자주 쓴다. 사람 기준으로는 "언제 합칠지"가 새로운 판단거리.

## 7. 온라인 (v0.5, 2026-09-26 추가)

### 7-1. 방식: 호스트 중계 락스텝

- 코어 시뮬은 결정론(정수 연산, 시드)이므로 **명령만 교환**한다. 상태는 보내지 않는다.
- 호스트가 **4틱(0.2초)마다 턴**을 만든다 = 그 사이에 들어온 모든 명령(자기 것 + 클라들 것 + 봇 것). 턴을 모두에게 보내고 자기도 적용한다.
- 클라는 받은 턴이 있어야 그 틱을 진행한다. 턴이 안 왔으면 기다리고("대기…" 표시), 3턴 이상 밀리면 빠르게 따라잡는다. 호스트는 아무도 기다리지 않는다 → 느린 클라가 호스트를 멈추지 못한다.
- 명령 지연 = 네트워크 왕복 + 최대 0.2초. 실시간 타워 디펜스라 체감 문제 없음.
- 25턴(5초)마다 호스트가 상태 해시를 실어 보내고, 클라는 자기 해시와 비교한다. 다르면 "[어긋남!]" 표시 (지금은 표시만, 복구는 나중).
- 클라가 보낸 명령의 팀·자리는 호스트가 그 클라의 슬롯으로 **덮어쓴다** (속이기 불가).
- 봇은 호스트만 돌리고 그 명령도 턴에 실린다. 사람이 나가면 그 자리는 호스트 봇이 이어받는다. 호스트가 나가면 판이 끝난다.
- 온라인에서는 정지·배속이 없다 (증강 10초 정지는 시뮬 안의 규칙이라 그대로).

### 7-2. 전송

- 지금은 **TCP 직결** (포트 27015). 같은 LAN 이면 호스트의 192.168.x.x 로 바로, 인터넷이면 호스트 공유기 포트포워딩 필요. 스팀 P2P 로 바꿀 땐 `INetTransport` 만 구현하면 된다.
- 메시지: Hello(이름) → Welcome(플레이어 id) → Lobby(인원수·플레이어·슬롯) … Start(시드·인원수·슬롯·턴 길이) → Commands(클라→호스트) / Turn(호스트→모두) / Ping·Pong / Leave / Chat.

### 7-3. 로비

호스트가 인원수(1v1/2v2/3v3)를 정하고, 사람 이름을 눌러 다음 빈 자리로 옮긴다(팀 바꾸기). 들어오는 사람은 첫 빈 자리부터 채운다: 1v1 이면 두 번째 사람이 상대, 2v2 이면 팀원. 빈 자리는 봇. 채팅 있음.

### 7-4. 검증

- 코어 테스트: 루프백으로 호스트·클라 세션이 한 판을 끝까지 돌려 **해시가 같음** (1v1, 2v2), 클라 명령 재태깅, 나간 사람 봇 대체, TCP 루프백 양방향 프레임.
- PlayMode: 로비 화면 생성, 호스트 경기 화면이 스스로 턴을 만들어 진행하고 클라 시뮬이 턴만으로 같은 상태가 됨.
- 실제 두 대 사이 플레이테스트는 아직. 같은 기계에서 빌드 두 개를 띄워(127.0.0.1) 확인 가능.

## 8. 첫 사람 플레이테스트 반영 (v0.5)

지현 피드백: "맵이 너무 짧다, 오는 걸 보고 대응할 시간이 있었으면", "초반부터 조금씩 샌다".

원인 (단일 라인 실험, 궁수만 지었을 때 웨이브별 누수):
- 유닛이 타워 사거리 안에 머무는 시간이 짧았다 (격자 5~8칸, 사거리 3 → 늑대가 사거리 안에 7초).
- 3웨이브 박쥐는 대공 타워(궁수·불사조)가 없으면 무조건 샌다. 4웨이브 보스 오우거(체력 540)는 궁수 6개로도 2 누수.

바꾼 것:

| | v0.4 | v0.5 |
|---|---|---|
| 라인 길이 | 20칸 | **30칸** |
| 타워 격자 위치 | 5~7칸 | **10~12칸** (라인 중간, 앞 10칸은 "오는 걸 보는" 구간) |
| 유닛 속도 배율 | 60% | **50%** (늑대 30초, 거북 86초에 통과) |
| 타워 공격 배율 | 150% | **140%** |
| 보내기 비용 배율 | 125% | **100%** (방어가 세진 만큼 보내기를 싸게 → 공격·방어 비율 유지) |
| 3v3 기지 체력 | 300 | 360 |

결과 (봇 스윕 16판): 1v1 누수 평균 16/40 (2:30까지 5), 판당 보내기 120회 (전 78회) — 초반은 잘 막히고, 보내기는 더 자주 한다. 2v2 파괴 3/16, 3v3 파괴 11/16 → 360 으로 올림.
궁수 6개(36골드)면 8웨이브까지 기본 웨이브를 다 막고, 궁수 4개 + 대포면 보스도 막는다. 대공 없는 조합(창탑·덤불만)은 여전히 박쥐에 샌다 — 의도.

## 9. 구불구불한 맵 (v0.6)

지현 피드백: "배치 칸을 늘리고 구석구석 두게", "일자 말고 원작처럼 구불구불한 구간이 있어야 효율적인 배치를 고민하는 재미가 있다".

### 9-1. 맵 = 격자 + 경로

- 맵은 격자(1v1 14×9, 2v2 18×12, 3v3 22×12). **경로**는 뱀 모양으로 가로 3~4줄을 3칸 간격으로 오가며, 유닛은 경로를 따라 걷는다 (진행도 = 밀리칸).
- **경로가 아닌 모든 칸이 타워 자리**(1v1 84칸). 원작처럼 아무 데나 짓되, 경로에서 멀면 쓸모없고 **굽이 안쪽 구석**은 세 구간을 동시에 본다 → 자리 고르기가 곧 전략. 봇도 "사거리 2.5 안 경로 칸 수"가 큰 자리부터 짓는다.
- 맵은 ASCII 로 정의한다 (`MapDef.FromAscii`): `.` 자리, `#` 경로, `S` 출발, `B` 기지, ` ` 빈 땅. `MapDef.Snake(w, h, runs)` 가 뱀 맵을 만든다. 손으로 그린 맵을 넣으려면 문자열만 추가하면 된다.
- 직업 시너지는 "같은 줄"이 사라져 **8방향 이웃에 같은 직업 타워**가 있으면 켜지는 것으로 바꿨다.
- 화면: 내 진영 왼쪽, 상대 진영 오른쪽 (나란히). 유닛은 방향에 따라 좌우를 본다.


### 9-2. 밸런스 (봇 스윕 16판)

굽이 구석 자리가 강해서 같은 공격 배율(140%)이면 누수가 7/40 로 뚝 떨어졌다 → **타워 공격 140% → 115%** (1v1 누수 평균 ~17/40, 2:30까지 1). 팀전은 누수가 기지 체력에 비해 너무 적어 **기지 2v2 120 → 80, 3v3 360 → 160**. 경로가 41칸이라 늑대 41초, 거북 2분 — 대응 시간은 충분하다.

## 10. 타워 역할 (v0.7)

지현 질문: "타워마다 광역·원거리 같은 역할이 있으면 좋겠다, 그건 조합으로 하는 건가?" → 기본 타워부터 역할이 갈리게 수치를 벌리고, 조합은 역할을 **합치는** 것으로 정리.

| 기본 타워 | 역할 | 수치 |
|---|---|---|
| 나무 궁수 | 단일·대공 | 공4 1.0/초 사3 |
| 가시 덤불 | 근접 광역·감속 | 공3 1.2/초 사1.5 광역1 감속30% (v0.7: 광역 추가) |
| 숲의 드루이드 | 지원·공격 오라 | 주변 +15% |
| 화염 창탑 | 화상 | 공4 1.0/초 사2 화상 3/초×3초 |
| 불꽃 술사 | 광역 | 공7 0.6/초 사2 광역1.2 |
| 불사조 | 대공 특화 | 공8 0.9/초 사3.5 공중 2배 |
| 태엽 포탑 | 원거리 저격 | 공14 0.4/초 사4.5 |
| 강철 대포 | 소광역 강타·대거인 | 공24 0.3/초 사3 광역0.7 거인 2배 |
| 수리 드론 | 지원·공속 오라 | 주변 기계 +25% |

- 새 공격 방식 **연쇄**(`ChainCount/ChainRange10/ChainPercent`): 맞은 유닛에서 1.5칸 안 다른 유닛으로 튄다. 번개 비행선(불사조+수리 드론)이 3회 70%.
- 역할은 수치에서 자동 분류(`TowerRoles.Of`)해서 상점 아이콘·선택 설명·행동 패널·합성표에 "[광역·감속]"처럼 보인다. 테스트로 기본 9종의 역할이 서로 다른지 확인한다.
- 광역 타워는 투사체가 닿을 때 폭발 이펙트.
- 밸런스: 광역이 늘어 팀전 누수가 줄어 기지 2v2 60 / 3v3 100 으로 낮춤 (1v1 40 유지, 봇 스윕 누수 19/16).

## 11. 해금 (v0.8)

|---|---|---|
| first_win | 첫 승리 | 칭호 새내기 지휘관 |
| flawless | 누수 0 승리 | 맵 굽이 다섯 (14×15, 긴 뱀 길) |

## 13. 후반 공격 스케일 (v0.10)
